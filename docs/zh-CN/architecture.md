## 查询流水线

每个问题经过三个阶段：

1. **规划** — LLM 分析问题并拆解为检索步骤（查哪些文档、哪些章节、
   对比什么）。
2. **检索** — 在租户的文档库上混合检索：FTS5 全文检索负责精确词项匹配，
   sqlite-vec 向量检索负责语义召回，结果合并排序。
3. **合成** — LLM 基于检索到的证据生成最终答案，并附来源引用。

流水线由 LLM 驱动：core 中没有任何硬编码的领域规则。

## 行业包

领域知识存放在 core 之外。*行业包*是一个 YAML 规则目录（词汇、实体别名、
查询提示），通过 `RetrievalPlugin` hook 在查询与入库时注入。行业包从
`industries/` 目录及 `OPENLAD_INDUSTRIES_DIRS` 指定的额外目录中发现。

仓库附带一个完整示例包（半导体）和三个空模板（法律、金融、通用）——
复制模板即可构建自己的行业包。这个分层保证 core 行业中立：通用机制进
`core/`，领域词汇进行业包。

## 多租户

每个租户在数据目录下拥有独立的 SQLite 数据库和向量空间。用户只属于一个
租户；用户名全局唯一。管理面板（`/admin`）负责用户、API 密钥、文档和
模型端点的管理。
